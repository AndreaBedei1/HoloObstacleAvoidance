## 1. Why this document exists

The scientific boundary of the project is `/perception/obstacles_raw`
(`docs/EXPERIMENTAL_BOUNDARY.md`). In simulation that topic is
manufactured; in reality it comes from `scripts/real/anchor_detect.py`
through `avoid_mission.py`. The observation model is therefore the only
place where the real sensor enters the simulated experiment.

The convenient model would have been
`measured_range = true_range + N(0, sigma)` with `sigma` taken from the
MAE already quoted in `docs/REAL_POOL_EXPERIMENT_LOG.md` (0.44 m). This
analysis exists to show that such a model is wrong **in kind**, not
merely in scale: over the range interval the pilot actually covered, the
real monocular range does not track the true range at all (Section 5).
A Gaussian-around-truth model would hand the simulated planner a sensor
strictly better than the one that exists, and every sim-to-real
conclusion drawn on top of it would be optimistic by construction.

is exactly the survivor bias the manifest was written to prevent.

## 3. Ground truth, and what it is not

The overhead RealSense gives the ROV pixel each cycle; the anchor's
suspension point is the fixed pixel (1069, 635); the scale is 402 px/m.
`gt_dist_px / 402` is the ground-truth range used throughout.

It is a **proxy**, not metric truth, and the model file says so:

* it is a *planar* distance in an oblique overhead image, compared
  against a *slant* range from the camera;
* the 402 px/m scale holds on one depth plane; the ROV and the anchor
  are not on it;
* it is measured to the anchor's **suspension** point while the camera
  measures the anchor **body** hanging below it.

All three errors are small compared with the effects reported below
(tens of centimetres against a residual spread of metres), but they are
not zero, and no absolute accuracy is claimed for the overhead system —
consistent with `docs/PHASE9_REAL_CAMPAIGN_PROTOCOL.md`.

## 4. Method

**Recovering the covariates.** `avoid_mission.py` computes
`range = 0.80 * 1277 / (width * 1920)` and
`bearing = atan2((center_x - 0.5) * 1920, 1277)`. Both are invertible,
so width and `center_x` are recovered exactly on the ground-truth
sessions. The inversion is verified against the 12 cycles that log both
a `det` block and a range: max error 1.4e-3 in width and 5.5e-4 in
`center_x`, which is exactly the quantisation of the logged values
(range is rounded to 0.01 m). **Width is a 1:1 function of the logged
range**, so "residual vs width" is the range regression
re-parameterised, not independent evidence. It is reported and labelled
as such.

**Per-cycle vehicle position.** The overhead pixel is not stored inside
each cycle, but `traj` receives one entry per cycle in which the tracker
found the vehicle — i.e. exactly the cycles with a non-null
`gt_dist_px`, in order. The script reconstructs the pairing and then
*verifies* it by recomputing `gt_dist_px` from the reconstructed pixel:
max error 0.05 px on all three sessions, i.e. rounding. If the check
failed, bearing analysis would be skipped for that session.

**Intervals.** Consecutive cycles are strongly autocorrelated (the
vehicle moves smoothly; lag-1 autocorrelation of the accepted series
reaches 0.90). An IID bootstrap would therefore understate every
interval. All confidence intervals are **moving-block bootstrap**
(5000 resamples, block length chosen from the first non-positive
autocorrelation lag: 9 cycles for the range residual, 6 for bearing).
Binomial proportions use Wilson intervals, which stay honest at the 0/n
and n/n counts this dataset keeps producing.

**Nothing is fitted that the data cannot support.** With n = 59 paired
samples from 3 sessions, only single-parameter comparisons and binned
summaries are attempted. Where a fit is reported, its confidence
interval is reported with it, and where the interval is uninformative
that is stated rather than hidden behind a point estimate.

## 5. Result 1 — monocular range vs overhead ground truth

n = 59 paired samples, 3 sessions, true range 0.371–2.376 m.

### 5.1 The sensor is censored from below

`detect_anchor` searches for the anchor's arm span only within
+-0.22 of the image width around the shank, so the reported width
fraction **cannot exceed 0.44** and the derived range **cannot fall
below**

    0.80 * 1277 / (0.44 * 1920) = 1.209 m

Observed maximum width fraction: 0.4397; 8 of the 59 paired samples sit
within 1 % of the cap. The pile-up of trigger ranges at 1.21–1.24 m
across the pilot runs is this censoring, not a coincidence. It is
structure, not noise, and the observation model reproduces it.

### 5.2 Headline residuals

Residual = measured range - true range.

| Set | n | bias (m) | MAE (m) | RMS (m) | median (m) |
|---|---|---|---|---|---|
| all samples | 59 | +2.29 | 2.92 | 6.20 | +0.09 |
| non-gross (see 5.3) | 44 | **-0.31** | **0.53** | **0.61** | -0.43 |

95 % moving-block CIs on the non-gross set: bias [-0.65, -0.01],
MAE [0.33, 0.76], RMS [0.40, 0.80]. Range of the full residual:
-1.04 m to **+21.29 m**.

Quoting a single MAE for this sensor is therefore misleading in both
directions: 2.92 m over-states the error in the regime where the
detector works, and 0.53 m hides that a quarter of accepted samples are
wrong by more than a factor of two. The previously recorded "MAE 0.44 m"
in `docs/REAL_POOL_EXPERIMENT_LOG.md` is a *conditional* number of the
second kind; it is not contradicted here, but it is incomplete.

Per session (non-gross): 193827 bias -0.05, MAE 0.33 (n = 22);
194145 bias -0.61, MAE 0.75 (n = 20); 195048 n = 2, not interpretable.
Session-to-session bias differs by more than the pooled CI, i.e. the
bias is not a constant of the sensor.

### 5.3 Gross failures are a separate mechanism

Define a **gross failure** as measured/true outside [1/2, 2]. 15 of 59
accepted samples (25.4 %, CI [16.1, 37.8]) are gross, and they are
perfectly separated by true range:

* every gross failure occurred at true range <= **0.993 m**;
* every non-failure occurred at true range >= **1.031 m**.

The mechanism is visible in the recorded frames
(`missions/20260814_193827/key_2.png`): inside about 1 m the anchor's
arms leave the band the detector searches for the arm span, the measured
width collapses to the shank alone, and the range explodes — up to
22.17 m measured at 0.88 m true. This is the worst possible failure
placement for collision avoidance: the sensor fails **towards "far
away"** exactly when the obstacle is closest.

The separation threshold is not tuned: it is where the geometry changes,
and it survives the sensitivity check of Section 10.

### 5.4 Does the residual depend on the observables?

Spearman correlation with the residual, 95 % moving-block CI:

| Observable | Spearman | CI | Verdict |
|---|---|---|---|
| true range | **-0.90** | [-0.96, -0.70] | real, strong |
| bbox width fraction | -0.87 | [-0.98, -0.62] | same relation re-parameterised, not independent |
| `center_x` | +0.07 | [-0.57, +0.45] | no evidence |
| \|`center_x` - 0.5\| | +0.12 | [-0.63, +0.81] | no evidence, CI spans everything |
| bbox height fraction | — | — | **not estimable** (never co-logged with GT) |
| detector score | — | — | **not estimable** (never co-logged with GT) |

On log-ratio instead of residual the picture is the same
(true range: -0.91). Restricted to the non-gross subset the dependence
on true range persists (Spearman -0.81), so it is not an artefact of the
failure regime alone.

Image position: no dependence is claimed. The non-gross subset shows
Spearman +0.69 against \|`center_x` - 0.5\|, but its CI is
[-0.63, +0.81] — with n = 44 autocorrelated samples spanning few
independent excursions, this is not evidence. It is listed as a
hypothesis for the next dataset, not a term in the model.

### 5.5 The simple model, fitted and then rejected

The natural parsimonious candidate is a multiplicative scale error, so
it was fitted on the non-gross subset:

    measured = 1.617 - 0.090 * true      R^2 = 0.010
    slope 95 % CI [-0.329, +0.055]       fit RMS 0.331 m
    Pearson(measured, true) = -0.10

A usable range sensor needs slope ~1. The estimated slope is **0.00
within error and 1 is far outside the interval**. Over the interval the
pilot covered (1.0–2.4 m), the measured range is *statistically
independent of the true range*: it sits near 1.4 m whatever the truth
is. The best pure scale factor (0.79) fits no better.

The binned view says the same thing without any model:

| True range (m) | n | gross | measured range, median (m) | residual median (m) | measured/true, median |
|---|---|---|---|---|---|
| < 1.00 | 15 | 15/15 | 11.23 | +10.66 | 19.74 |
| 1.00–1.60 | 15 | 0/15 | 1.42 | +0.20 | 1.17 |
| 1.60–2.00 | 15 | 0/15 | 1.23 | -0.47 | 0.72 |
| >= 2.00 | 14 | 0/14 | 1.28 | -0.86 | 0.59 |

The measured column is flat (1.23–1.42 m) while the truth doubles. Two
causes compound: the censoring floor of Section 5.1 clips everything
below 1.21 m, and the arm-span measurement is too noisy to resolve what
remains.

**Therefore no scale-error model is adopted.** What the data support is
an empirical, range-conditioned replay of the measurement itself, plus
an explicit failure regime inside 1 m. That is what
`observation_model_v1.json` contains.

## 6. Result 2 — bearing

Bearing ground truth is not logged, but it is derivable: the overhead
image gives the line from the ROV pixel to the anchor pixel, and the
vehicle's heading comes from the logged compass yaw. The missing piece
is the offset between the compass datum and the overhead image axes,
which was never calibrated.

That offset was estimated from straight `APPROACH` segments under a
**no-crab assumption** (the vehicle travels along its bow). Two sessions
have a usable segment and they agree:

| Session | n segments | offset (deg) | within-session sd |
|---|---|---|---|
| 20260814_193827 | 3 | 67.64 | 1.83 |
| 20260814_195048 | 9 | 66.38 | 3.44 |

Agreement to 1.26 deg across independent sessions is the only evidence
available that the calibration is real rather than fitted. The adopted
value is 67.01 deg.

Bearing residuals (camera minus derived truth), n = 59:

| Subset | n | mean (deg) | sd (deg) | MAE (deg) |
|---|---|---|---|---|
| all | 59 | -2.88 | 4.56 | 3.94 |
| non-gross range | 44 | -2.06 | 3.72 | 3.26 |
| true range >= 0.8 m | 49 | -2.43 | 3.93 | 3.50 |
| true range < 0.8 m | 10 | -5.10 | 6.72 | 6.09 |

95 % CIs: mean [-4.94, -1.56], sd [2.94, 5.34].

**What is validated:** the *dispersion*. About 4 deg of bearing scatter
is a real property of the detector's `center_x`, and it is the number
the model uses.

**What is not validated:** the *bias*. The mean residual and the frame
offset are not separable — a 1 deg error in the offset shifts all 59
residuals by 1 deg, and the offset is only known to about 1.3 deg
between sessions and 1.8–3.4 deg within them. The measured bias
(-2.9 deg) is of the same order as its own calibration uncertainty, so
no bearing bias is claimed. The model records the pool and flags
`bias_is_validated: false`.

A second caveat is geometric: the truth is the bearing to the anchor's
suspension point while the camera reports the bearing to the detected
blob centre. Inside 0.8 m the anchor subtends a large angle and the two
diverge — visible as the doubled residual sd in the last row above. The
close-range bearing residual is therefore an upper bound on the
detector's error, not a measurement of it.

## 7. Result 3 — availability and its temporal structure

Acceptance is the gate in `avoid_mission.accept()`: found, and
score >= 0.55, height >= 0.12, width >= 0.02. Median cycle period
0.255 s (0.27–0.28 s in the mission sessions).

| Session | cycles | accept rate | 95 % CI | lag-1 ac | p01 | p11 | G2 | p | verdict |
|---|---|---|---|---|---|---|---|---|---|
| 20260814_193827 | 85 | 0.435 | [0.34, 0.54] | 0.90 | 0.043 | 0.946 | 83.15 | 8e-20 | **Markov** |
| 20260814_194145 | 57 | 0.368 | [0.26, 0.50] | 0.62 | 0.143 | 0.762 | 22.33 | 2e-06 | **Markov** |
| 20260814_195048 | 52 | 0.038 | [0.01, 0.13] | -0.04 | 0.041 | 0.000 | 0.16 | 0.69 | underpowered |
| run_20260814_184449 | 43 | 0.163 | [0.08, 0.30] | 0.18 | 0.139 | 0.333 | 1.20 | 0.27 | underpowered |
| shadow_20260814_183518 | 57 | 0.035 | [0.01, 0.12] | -0.04 | 0.037 | 0.000 | 0.15 | 0.70 | underpowered |
| shadow_20260814_183600 | 47 | 0.064 | [0.02, 0.17] | -0.07 | 0.070 | 0.000 | 0.42 | 0.52 | underpowered |

"Underpowered" means fewer than 10 cycles in one of the two classes: the
test cannot detect burstiness there even if it is present, so those four
rows are **not** evidence for IID.

**Autocorrelation.** In the two powered sessions the accepted series
stays positively correlated to lag 10 (0.90 → 0.47 and 0.62 → 0.13).
Detection is not a per-frame coin flip. The apparent 0.48 spikes in the
low-availability sessions are the artefact of two accepted cycles two
apart and carry no information.

**Model comparison.** IID Bernoulli against a 2-state Markov chain by
likelihood ratio on the same n-1 transitions (df = 1, critical value
3.84):

* per session, where the test has power: G2 = 83.15 and 22.33 — IID is
  rejected decisively;
* pooled over within-session transitions (335 transitions): p01 = 0.072,
  p11 = 0.747, G2 = 131.7, p = 2e-30;
* stationary acceptance 0.221; mean detection run 3.94 cycles (~1.0 s),
  mean gap 13.9 cycles (~3.5 s).

Run lengths, pooled: detections `[1x13, 2x4, 16, 35]`, gaps
`[1x5, 2x3, 3x4, 4x2, 13, 14x3, 19, 29, 30, 32, 33, 40]`. The
distribution is not geometric — it is a few long spans plus singletons,
which the 2-state chain reproduces only approximately. Both the fitted
chain and the raw run-length pools are stored so a consumer can replay
the empirical spans directly instead.

**Caveat on the pooled figure.** Transitions are counted within sessions
only, so no cross-session splice is created; but pooling sessions whose
acceptance rates differ by an order of magnitude (0.04 to 0.44) still
inflates apparent persistence, because a mixture of Bernoulli rates
looks bursty. **The per-session tests are the trustworthy evidence; the
pooled G2 is an upper bound.** The correct use of the model is to draw
the session's acceptance rate first (dome cleanliness was the dominant
factor — 8 % dirty vs 46 % after wiping, per the protocol) and then run
the chain, rather than to simulate the pooled average, a condition that
occurred in no single run.

**Verdict: the data support a bursty (2-state Markov) availability
model, not IID Bernoulli.**

## 8. Result 4 — false positives

Three failures that must not be conflated.

**(a) Gross range failure** — real object, wrong measurement. 15/59
accepted samples, all inside 1 m (Section 5.3). This is a *measurement*
failure and the range model already carries it.

**(b) Accepted detection of the wrong object.** Bearing gives an
independent test, because it comes from `center_x` and not from the
width that produced the range. A detection inside the image is at most
`atan(960/1277) = 36.9 deg` off the bow, so a bearing disagreement
beyond 45 deg cannot be a correct detection of the anchor under a
correct overhead fix — a derived threshold, not a tuned one.

In the worktree dataset: **0 of 59** accepted samples exceed it
(95 % upper bound 6.1 %). Per-session mean bearing residuals are
-4.8, -0.2 and +6.1 deg. There is no evidence of a false positive
reaching the planner in these three sessions, and n is too small to
claim the rate is low.

The suggested alternative source — "runs that aborted at t = 0" — does
not exist in the worktree, and the aborted runs among the git-only
sessions logged 0–3 cycles each and aborted on the overhead **wall
guard**, not on perception. They carry no false-positive information.

**(c) Non-anchor detections below the gate.** The two shadow runs
(104 cycles) are the only direct evidence: the detector returned a box
on **100 %** of cycles, and 5 of them (4.8 %, CI [2.1, 10.8]) passed the
acceptance gate, with implied ranges of 9.45–13.61 m — far outside a 6 m
pool. Inspection of `shadow_20260814_183518/f0001.png` shows the box on
surface debris near the top of the frame while the anchor's shank is
visible elsewhere in the same image: these are detections of the *wrong
object*, not detections of a missing one.

**This rate does not describe the current detector.** All 104 of those
boxes are shorter than 0.25 of the frame, a height the committed v2
shape prior structurally cannot produce (it skips shorter candidates).
The shadow runs therefore predate v2, and the script dates every session
this way and records the verdict in the model file. The v2-compatible
session (`run_20260814_184449`) shows 7 detections, all with height
0.387–0.431. Two further observations follow: the false-positive rate of
the *current* build is simply not measured by this dataset, and a
downstream range sanity bound (reject > pool diagonal) would have
rejected all five of these regardless of the detector.

## 9. Result 5 — score distribution

Available only in the `avoid_runs` sessions (111 detections), which have
no ground truth, so **accepted/rejected is the gate's own label, not
truth**.

| Class | n | median | IQR | min | max |
|---|---|---|---|---|---|
| accepted | 12 | 0.869 | 0.684–0.995 | 0.569 | 1.131 |
| rejected | 99 | 0.520 | 0.433–0.756 | 0.173 | 3.504 |

Rank overlap against the gate label: AUC 0.77.

The important observations are the negative ones:

* **42 of the 99 rejections (42 %) passed the score threshold** and were
  rejected on bbox size. The gate is driven by geometry, not by score.
* Median bbox height is 0.388 for accepted and 0.070 for rejected — a
  clean separation, unlike score.
* **The single highest score in the dataset (3.504) belongs to a
  rejected detection**, one of the shadow-run false positives. A
  confident score is not evidence that the object is the anchor.

Since no score is co-logged with ground truth, score cannot be used to
condition the range error, and the model does not do so.

## 11. What the model file contains, and how to use it

`observation_model_v1.json`, `kind: EMPIRICAL_REPLAY`.

* **Range.** Empirical pools binned on *true* range
  (<1.0 / 1.0–1.6 / 1.6–2.0 / >=2.0 m). Both the measured ranges and the
  residuals are stored, but they are not interchangeable: with a slope
  near zero, adding a residual pool to the true range implies an
  accuracy the sensor does not have. **Sample the measured range
  directly** from the bin's pool and clamp to the 1.209 m floor. The
  innermost bin already contains the gross failures at their observed
  frequency, so no separate failure process is needed.
* **Bearing.** Additive residual pool (59 values), with
  `bias_is_validated: false` and the frame-offset caveat attached.
* **Availability.** 2-state Markov (`p01`, `p11`) plus the raw
  run-length pools and the per-session rates. Draw the session rate
  first, then run the chain; cycle period 0.255 s is recorded so run
  lengths convert to seconds.
* **False positives.** All three failure types, each with its own
  scope, plus the per-session detector-build dating.
* **Score.** Distributions only, with the explicit note that they
  cannot condition the range error.
* **`not_supported_by_this_dataset`.** A machine-readable list of the
  six things a consumer must not read out of this file.

**Why bootstrap/replay rather than fitted Gaussians.** Three reasons,
all empirical: the measurement is censored at a hard floor; the error
distribution is bimodal (a metre-scale regime and an order-of-magnitude
failure regime) and its two modes are selected by the true range; and
the availability process is bursty. A Gaussian reproduces none of the
three, and with n = 59 from 3 runs there is no basis for estimating a
parametric shape anyway. Resampling the observations makes the model's
support explicit — it can only produce what was actually seen — which is
the correct behaviour for a calibration this thin.

## 12. Limitations

1. **n is small.** 59 paired range samples from 3 sessions; 44 outside
   the failure regime; 2 usable sessions for the availability test; 12
   detections with both a score and a gate decision. Several reported
   intervals are wide enough to be compatible with no effect, and are
   labelled as such.
2. **One session, one afternoon, one lighting condition.** Everything
   was recorded on 2026-08-14 in one pool under one sun angle and one
   turbidity. No dependence on lighting or water clarity can be
   estimated, yet dome cleanliness alone moved acceptance from 4 % to
   44 % — so this is not a small unknown.
3. **One obstacle.** A single suspended anchor of 0.80 m arm span. The
   width-based range, the shape prior and the failure mechanism are all
   properties of that object. Nothing here transfers to another
   obstacle.
4. **Detector version drift within the dataset.** Two shadow runs
   predate the v2 shape prior; the mission sessions bracket the commit
   that introduced it. Sessions are dated in the model file, but no run
   can be re-attributed with certainty because the detector was not
   version-stamped into the logs. *Recommendation: log a detector
   version and the full `det` block in every future run — the single
   change that would have made this analysis complete.*
5. **Ground truth is a proxy** (Section 3), and the bearing truth rests
   on a no-crab assumption (Section 6).
6. **The failure threshold near 1 m is a boundary of the observations,
   not a calibrated curve.** True ranges below 0.37 m and above 2.64 m
   were never observed, and the model must not be extrapolated there.
7. **Pilot data.** The runs were bring-up, not an experiment. They are
   admissible as model input only, and the final campaign must be a
   separate, prospective, frozen dataset.

## 13. Reproducing

```
python scripts/analysis/characterize_observations.py
python scripts/analysis/characterize_observations.py --include-git-missing
```

Read-only and offline: reads `log.json` files, writes into
`experiments/real/observation_model/`. No vehicle, no camera, no MAVLink
connection. The second command writes to a separate filename so a
sensitivity run cannot overwrite v1.
