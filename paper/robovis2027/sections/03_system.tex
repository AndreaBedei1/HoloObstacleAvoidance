\section{System and the Perception-to-Actuation Pipeline}
\label{sec:system}

\subsection{Vehicle and basin}

The platform is an eight-thruster BlueROV2 Heavy running ArduSub over a
tether, with a forward \num{1080}\,px camera. It has neither Doppler
velocity log nor acoustic positioning and therefore no absolute or
velocity-referenced pose. The basin is a rectangular pool of roughly
\SI{6}{\metre}$\times$\SIrange{2.7}{3.0}{\metre}, with the obstacle -- a
\SI{0.5}{\metre}-class anchor -- suspended from a transverse rod.

\subsection{The pipeline and the boundary that both domains share}

The stack is a chain of ROS\,2 nodes, and the same source code runs in
both domains between two fixed points:
\begin{multline*}
\texttt{/perception/obstacles\_raw} \rightarrow \text{qualification}
\rightarrow \text{estimator} \\
\rightarrow \text{planner} \rightarrow
\texttt{/planner/cmd\_vel\_safe}.
\end{multline*}
The source code within this boundary is identical in both domains. Raw
observation producers and command consumers differ. This shared boundary
defines the command-domain comparison; Section~\ref{sec:deployment}
documents the deployment changes.

\emph{Qualification} requires mutually coherent updates before declaring
a valid track, suppressing single-frame false positives at the cost of
delay.

\emph{Estimation} uses a fixed-gain Kalman filter on image position and
extent and predicts through observation gaps. The same variant is fixed
for every run.

\emph{Range} is monocular and deliberately simple. An object of assumed
physical height $H$ whose bounding box fills a fraction $h$ of the image
subtends $\theta = h \cdot \mathrm{vfov}$, giving
\begin{equation}
R = \frac{H/2}{\tan(\theta/2)} .
\label{eq:range}
\end{equation}
Both planners use this implementation and the same assumed height. Their
range inversion used the \SI{90}{\degree} node default in both domains;
the frozen observation relay alone used \SI{60}{\degree} when applying
its detection-probability model (Section~\ref{sec:limitations}).

\subsection{The two planners}

The \emph{committed} planner is a finite-state controller. Below an
engagement range it commits to one side, holds that side for a minimum
duration, strafes to a clearing offset, runs past the obstacle and
returns to the original line. Its side choice depends only on where the
obstacle appears in the image, which is the property
Section~\ref{sec:realresults} tests. Its manoeuvre geometry -- the
clearing offset and the run-past margin -- is the pair of parameters that
turns out not to fit the basin.

The \emph{holonomic dynamic-window} baseline~\cite{fox1997thedynam}
scores velocity candidates for clearance, progress, speed, route
adherence and smoothness. It requires a pose estimate to project
candidates and evaluate route adherence.

\subsection{Actuation}

Simulated commands pass to a vehicle-dynamics model in HoloOcean.
Physical commands map to ArduSub joystick channels through
\begin{equation}
c = \operatorname{sign}(v)\left(d + \frac{|v|}{k}\right),
\label{eq:deadband}
\end{equation}
where per-direction gain $k$ and deadband $d$ are fitted from open-water
trials. S3 applies the fitted response downstream of the planner.
